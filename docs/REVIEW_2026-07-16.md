## P0 — Blockers (live in production now)

### P0-1. There is no server-side price verification in production. A buyer can invoice themselves any amount.

**File:** `supabase/functions/place-order/index.ts` (deployed = `main@9e4e3d0`), array declared at `:696`, read at `:1241`, `:1505`, `:1508`, `:1515`, `:1519`.

The deployed function declares `priceMismatches` and reads it in five places — **but never writes to it.** Verified:

```
git show 9e4e3d0:supabase/functions/place-order/index.ts | grep -c "priceMismatches.push"
→ 0
```

The array is permanently empty, so the `⚠` email subject flag, the `order_events` warning, and the operator log **never fire**. Meanwhile the file header (`:18-26`) states: *"every line is now CHECKED server-side against the admin-set price."* **That comment is false in production.**

`grossSubtotalCents` and `order_lines.unit_price_cents` are taken verbatim from the client. Payment is manual Zelle, so the only control is an operator eyeballing a total with no signal telling them to.

**Attack:** POST a valid order with `unitPriceCents: 1` on a $600 case. Order is created at $0.01. No flag, no log, no event.

The project's own commit message for the fix says it plainly: *"the priceMismatches array was never populated — a buyer could invoice themselves any amount."*

**Fix:** Deploy `7860e57` (`priceCheck.ts` — pure, already unit-tested at `tests/unit/priceCheck.test.ts`). The code is written. It is not deployed.

### P0-2. Four notification functions are ungated — any signed-up customer can read any order's PII and email arbitrary buyers.

**Files (deployed):** `supabase/functions/send-receipt/index.ts`, `send-processing-notification/`, `send-delivered-notification/`, `send-shipment-notification/`.

`send-receipt` accepts `{ order_id }` and returns `{ ok, html }` — the **full rendered receipt** (name, contact, address, line items, totals) — and `{ order_id, preview: true }` returns the HTML with no write (`:9-11`, `:32-33`). The only protection is platform-level `verify_jwt: true`, which authenticates *any* user, not an admin. There is **no `is_admin()` / authorization check** in the deployed file.

**Attack:** Sign up (free, self-serve). Call `send-receipt` with any `order_id` → full PII for any order in the system. Classic authenticated IDOR. Without `preview`, it also **emails the buyer and stamps `receipt_sent_at`** → mass-email any customer.

`_shared/adminGate.ts` **already exists on `main`** — `send-receipt` simply doesn't call it. The wiring (`requireAdmin(req)`) is branch-only.

**Fix:** Deploy `7860e57`.

### P0-3. The server grants 27–40% wholesale on **any SKU in the catalog**, priced off the client's own number. Unbounded, silent margin loss.

**File:** `supabase/functions/place-order/index.ts:795-825`. Live on `main@9e4e3d0` at `:898-916` — **both branches.**

The client offers wholesale on **biopeptides only** (`BiopeptideResearchSupplies.tsx:121`), and only for doses passing three filters (`wholesale.ts:55-64`: public, tracked, priced > 0). The server applies **none of them**. Verified: `slowByKey` — the only thing built from the `product_variant_stock` query — is referenced at exactly two places (`:801` `isSlow`, `:819` B2G1). **It never gates wholesale.** Grepping the whole wholesale block on the deployed build for `category|biopeptide` returns **0**.

Server eligibility reduces to: non-empty `sku` + **client-sent** `unit > 0` + `qty >= 3` (`:799`).

**Scenario:** a signed-in buyer adds 10 × a `laboratory-equipment` item at $200. `:812-818` → `cases = 1`, `packValue = Math.round(10 × 20000 × 40 / 100)` = **$800 off** — on a product no tile ever offered wholesale. It also forces `fast = false` (`:848`) and suppresses the account discount, reward voucher, and B2G1 (`:856-858`).

No promo gate, no admin switch, no expiry. The cart quotes full retail (there is no client-side wholesale estimate — `CartPage.tsx:685` sums plain `lineUnitCents`), so the buyer is **quoted retail and invoiced 27–40% less** and never knows. This is the exact mirror of P0-5: same root cause, opposite direction, and it drains margin rather than trust.

The intent is genuinely ambiguous — `:748` says *"Offered on EVERY orderable dose"*, and "dose" implies compounds while the code says any SKU. **Either reading, client and server disagree and the money is real.**

**Fix:** gate the wholesale plan on the matched priced variant row the function *already loads* into `slowByKey`. The data is in hand and unused.

### P0-4. Non-monotonic pricing: a guest buying 10 vials pays **$240 more** than buying 9. Live now.

**File:** `supabase/functions/place-order/index.ts:821-825` (arbitration) + `:840-842` (guest gate). Present on `main@9e4e3d0` at `:914` / `:934` — **both branches affected.**

The wholesale/B2G1 arbitration is a hard `else-if`: a line routed to `wholesalePlan` can never enter `b2g1FreePlan`. The account gate then drops the whole wholesale plan for guests — **with no re-arbitration back to B2G1**.

Worked example, $60 slow-ship vial, guest, B2G1 live:

| qty | Branch | Discount | Total |
|---|---|---|---|
| 9 | `packValue $81 < b2g1Value $180` → B2G1 | −$180 | **$369.99** |
| 10 | `packValue $240 ≥ b2g1Value $180` → wholesale → **dropped** | $0 | **$609.99** |

**This is live.** Queried production directly:

```json
promo_settings → {"b2g1_enabled": true, "b2g1_ends_at": null, "b2g1_excluded_skus": []}
```

Hits every guest, not just members. Adding one vial to the cart raises the bill by $240.

**Fix:** Re-arbitrate after the guest gate — if `wholesalePlan` is dropped, re-evaluate those lines for B2G1 eligibility instead of discarding them.

### P0-5. Client and server use different definitions of "member". A member who types a different email is silently billed as a guest.

**Files:** client `src/layout/CartDrawer.tsx:81-82`, `src/pages/CartPage.tsx:71-72` (`isMember = !!user`) vs server `supabase/functions/place-order/index.ts:618-643` (`stampedUserId`).

The server stamps ownership **only** when a verified JWT resolves **and** `contactIsEmail` **and** `authedEmail === contact.toLowerCase()` (`:628`, `:635`). The client asks only *"is this person signed in?"*

Neither cart surface prefills, validates, or even reads `user.email` — both are `useState('')` (`CartDrawer.tsx:94`, `CartPage.tsx:96`). `CartPage` is labelled **"Email or Phone *"** (`:817`) and applies **no format check** (`:124`), so it actively invites a phone number, which fails `contactIsEmail` and *also* suppresses the invoice email entirely (`:1333`).

Everything gated on `stampedUserId` silently evaporates:

| Perk | Client shows | Server bills | Gap |
|---|---|---|---|
| Shipping | "Free — member" (`CartDrawer:662`, `CartPage:729`) | `999¢` (`:685-687`) | **+$9.99** |
| Wholesale case ×10 | "−40%, applies automatically" (`WholesaleTile.tsx:369-381`) | plan dropped → **retail** (`:840-842`) | **+$240** on a $60 vial |
| Wholesale half kit ×5 | −27% | retail | +$81 |
| Account discount | `−$X` row (`CartDrawer:647-656`) | `if (stampedUserId)` (`:649-672`) | full percent |
| Reward voucher | "applied automatically at next checkout" (`RewardTracker.tsx:87-88`) | `if (stampedUserId)` (`:693-706`) | 40% of top unit |

**Headline:** member, one $60 case, types a different email → tile promises **$360**, drawer says **$600**, server bills **$609.99**. **+$249.99 (+69.4%) versus the advertised price.**

**Why nothing catches it:** the client sends an *honest retail* `unitPriceCents` — the 40% only ever existed as a server-side synthetic `order_coupons` row (`:1217-1229`) that the gate deleted before creating. So even once P0-1 is fixed, the price check **still won't catch this**: it verifies *unit prices*, and every one of these perks is a *discount or shipping*. Clean check, wrong total.

**Fix:** Bind the contact field to the session — prefill from `user.email` and either lock it or warn explicitly that perks require the account email. Server-side, prefer resolving membership from the verified JWT alone and treat the contact as a *delivery* address, not an identity claim.

## P1 — Should fix before the next deploy

### P1-1. Reward voucher can be double-spent (TOCTOU)
`place-order/index.ts:693-706` (read) → `:1190-1211` (consume). The voucher is read early, the order committed at `~:1082`, and the CAS update runs *after*. The update is correctly filtered (`.eq("status","active")`) so only one row flips — but **the code never checks whether it matched**. A filtered UPDATE matching nothing returns `error: null`, so the loser silently keeps the discount.
Two concurrent checkouts with different `idempotency_key`s → one voucher, two 40% discounts.
The coupon path already solves this (`redeem_coupon`, `SELECT ... FOR UPDATE`, plus rollback at `:1252-1293`). The voucher path is the one place missing the pattern this codebase already invented.
**Fix:** atomic consume via RPC returning the row; roll back like the coupon path if it lost.

### P1-2. B2G1 eligibility is spoofable — and one collision already exists in live catalog data
`place-order/index.ts:788`, `:795-826`. `isSlow` is a `.some()` OR across *every* dose row for the SKU, matched against `squash(product.name + note)` — both client-controlled.

**It fires on real data today, no attacker needed.** Squashing every same-SKU dose pair in `biopeptideCompounds.generated.json`, exactly one collides:
```
sku VSR-RS-IGF (igf-1-lr3), variants ["0.1mg","1mg"]
squash("igf-1lr3—0.1mg").includes("1mg") === true
```
If `1mg` is sourced (slow) and `0.1mg` is in stock (fast), ordering 3 × "IGF-1 LR3 — 0.1mg" matches the slow `1mg` row → `b2g1Free = 1` (`:819`) → a free vial on a line that must not qualify.

**And `note` is attacker-controlled** (`:800`): post 3 × "X — 20mg" with `note: "5mg"` where `5mg` is slow → free 20mg vial. At qty 30 → 10 free. B2G1 becomes attacker-driven whenever `b2g1_enabled` is on — **which it is.**

`priceCheck.ts` already solved this class — longest-match wins, with a regression test at `tests/unit/priceCheck.test.ts:119` (*"'15mg' is never claimed by the '5mg' row"*). The hardening was never applied to this second, independent matcher.
**Fix:** export the resolver from `priceCheck.ts` and use it in both places; match against `product.name` only — `variantProduct` (`cartActions.ts:54`) bakes the dose in there by construction. `note` is free text and must never be an identity signal.

### P1-3. Price check skips SKUs with disallowed characters — no flag at all
`place-order/index.ts:566-602`, `priceCheck.ts:116-139`. Lines failing `SKU_RE` are dropped from both the query *and* the report. `"sku": "BPC-157 "` (trailing space) + any price → not even the "unresolved" flag the anti-evasion work exists to produce. Worse than the case it was built to catch. *(Applies once P0-1 is deployed.)*
**Fix:** treat `SKU_RE` failure as a mismatch with `serverCents: null`.

### P1-4. The drawer shows a Total that contradicts the Total 40px above it
`src/layout/CartDrawer.tsx:627-636`. `breakdown` is computed **only if `accountDiscount` is truthy**, so a coupon applied without an account discount is **omitted from the Total entirely** — it overstates. Meanwhile `PromoCode` renders its *own* total (`PromoCode.tsx:65`, `:200-205`) computed *without* the account discount and *without* shipping. Two contradictory "Total" figures on one screen.
The drawer total is also blind to wholesale, B2G1, and the reward voucher — wrong even on the happy path.
`CartPage` has **no grand total at all** (`:683-716`, `:727-730`) — only Subtotal, "Total after discounts" (excl. shipping), and a separate Shipping row.
**Fix:** one shared total function, fed by the same inputs the server uses.

### P1-5. The cart drawer is a dialog in name only
`src/layout/CartDrawer.tsx:236-248` declares `role="dialog" aria-modal="true"` but has **no focus trap**, no initial focus, and no focus restore on close (trigger: `GlobalHeader.tsx:86-99`). The app root is never `inert`/`aria-hidden` (`GlobalSurface.tsx:18-29`), so keyboard users tab straight through the scrim into the page behind. Same gap in `NavDrawer.tsx` and `MemberAccessGate.tsx:164`.
`DisclaimerGate.tsx:54-81` implements a correct trap — use it as the reference.
Also `CartDrawer.tsx:464-473`: the only control with `focus:outline-none` and **no** focus-visible replacement (WCAG 2.4.7), at ~14px tap height (WCAG 2.5.8).
**Fix:** extract `useFocusTrap(open, ref)` from `DisclaimerGate`; reuse in all three.

### P1-6. `$0` order lines are still reachable — the old bug in a new shape
`src/lib/cartActions.ts:117` — `return tierPriceCents(item.product, dose) ?? 0;`. `tierPriceCents` (`pricing.ts:29`) matches `/([\d.]+)\s*mg/i`, so a **non-mg dose returns null → `?? 0` → the line is billed $0.** Six live catalog doses hit this, all with `priceCents: null`: `hcg` (1000/2000/5000/10000iu), `lemon-bottle 10ml`, `lipo-c 10ml`.

The tile still renders Add — `isVariantPublic` **defaults true** for an untracked dose (`productOverrides.ts:250`) and `formatPrice(null)` shows `—` (`pricing.ts:51`). The server won't catch it either: `priceCheck.ts:78` filters to `price_cents != null`, so a SKU with no priced rows is **skipped, never flagged** (`:128`).

`canQuickAdd` (`cartActions.ts:88`) exists and would block this — but only **2 of 11** call sites use it (`InventoryRow.tsx:57`, `InventoryTable.tsx:93`). Unguarded: `CompoundTile.tsx:92`, `CompactProductTile.tsx:70`, `ProductCard.tsx:66`, `BiopeptideInventoryModal.tsx:52`, `CompoundIntelligenceOverlay.tsx:174,236`, `ProductPage.tsx:151`, `CompoundIntelligenceHero.tsx:368`.

This is the historical `add(product)` $0-line bug that already hit prod — the dose now survives, but the price doesn't.
**Fix:** make `lineUnitCents` return `number | null` and have the payload builders (`CartDrawer.tsx:193`, `CartPage.tsx:188`) refuse null lines; flag `$0` unconditionally in `priceCheck`.

### P1-7. `npm run gen:inventory` is a landmine — confirmed, and worse than "hand-diverged"
Replayed the generator's mapping against the manifest without writing:

WOULD ADD:  10-amino-1mq        WOULD DROP: korean-glutathione

Precise mechanism: **`korean-glutathione`** (`VSR-RS-GSK`, `1200mg`) has **no META entry and no manifest row** — it was hand-written into the *generated* file, so the generator cannot reproduce it. **`10-amino-1mq`** has both and was hand-deleted. `buildInventory.mjs:241` `writeFileSync` overwrites wholesale: korean-glutathione is destroyed, 10-amino-1mq returns with **no price rows → formula-priced**.

`buildInventory.mjs:15-17` still claims *"Deterministic… byte-identical output (no git churn)"*. **That claim is now false**, with no warning banner.

### P1-8. The placeholder pricing formula produces absurd numbers, and it is a live fallback

## Things that are genuinely right

Worth stating, because the engineering here is better than the deploy story suggests:

- `stampedUserId` uses `auth.getUser(bearer)` — a real round-trip to GoTrue, not a local decode. No forgery path found.
- `clampQty`/`clampCents` (`:214-223`) correctly reject `NaN`/`Infinity`/negatives; `discountCents` is capped at `grossSubtotalCents` (`:1030`), so `totalCents` can never go negative — verified algebraically.
- `redeem_coupon` uses `SELECT ... FOR UPDATE` and `place-order` **rolls back** on a lost race (`:1252-1293`). Textbook.
- Email HTML is consistently `escapeHtml()`'d; `to`/`reply-to` only ever get `contact` after an anchored `EMAIL_REGEX` that rejects `\r`/`\n` — header injection closed.
- CORS is a fixed origin, never `*`, never reflected. Turnstile fails **closed**. No secrets in logs or responses.
- Idempotency: read-before-write plus a `23505` unique-constraint backstop.
- Fonts: all 7 faces `font-display: swap`, exactly 4 preloaded (the genuinely most-used weights), 13–17K subsets, all files present — no "preloaded but unused" flag.
- `prefers-reduced-motion` **does** flatten the drawer slide (the `!important` blanket in `theme.css:496-514` beats the inline transition) — correct, though incidental rather than explicit.
- Wholesale is correctly account-gated from the *verified* session and correctly suppresses competing discounts. The design is right; the guest fallback (P0-4) and the missing catalog gate (P0-3) are the bugs.
- `effectiveTierPriceCents` vs `tierPriceCents`: the cart resolves through `variantPriceCents` (`cartActions.ts:112-118`), so admin overrides **are** honored. The known price-path trap is **not** tripped.
- **Integer-cents discipline is clean.** `tierPriceCents` rounds dollars *then* ×100 (`pricing.ts:35`), so results are always multiples of 100; `wholesalePackPricing` outputs are all integers (`:105-113`); `clampCents` floors (`index.ts:222`). **No path was found where a fractional cent reaches an order line or a displayed price.** The only artifact is the display-only `perVialCents` (`wholesale.ts:113`), which is documented as a comparison figure and never billed.
- **NaN cannot reach a price.** `tierPriceCents:32` guards `!Number.isFinite(mg)`, so `".mg"` → NaN → falls back.
- Missing chem facts are handled deliberately: 14 of 50 compounds lack `casNumber`/`molecularWeight`, and the generator prints an explicit "shipped WITHOUT full chem facts" warning (`buildInventory.mjs:117`, `:250`). All 50 have images and non-empty `variants`. No surface renders `"null"`/`"undefined"` to a user.
